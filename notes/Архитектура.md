# The Wind Engine — архитектура

Движок под одну игру: тактический шутер с видом сверху в духе Running With Rifles.
Не универсальный движок. Всё, что не нужно этой игре, не делаем.

Подробности решений: [[Rust и wgpu вместо Vulkan]], [[Мир — сетка 2.5D]],
[[Сеть — снимки и дельты]]. Ход работ: [[Веха 0 — симуляция]], [[Веха 1 — сеть]].

## Цели

| Что | Цель |
|---|---|
| Солдаты на карте | сотни, в перспективе 1000+ (ИИ + игроки) |
| Живые игроки на сервере | до 24 |
| Карты | большие, километровые |
| Камера | как в RWR: сверху под углом, следует за игроком |
| Стиль | low-poly, персонажи и объекты из вокселей |
| Разрушаемость | важна: стены, заборы, постройки |
| Инструменты | встроены в движок, оформление в духе Blender |

## Главные принципы

1. **Симуляция отдельно от графики.** `wind_sim` ничего не знает про окно, GPU и звук.
   Сервер — это симуляция без окна. Клиент — симуляция + отрисовка.
2. **Сервер решает всё.** Клиент шлёт ввод, сервер присылает состояние. Читерить нечем.
3. **Детерминированный генератор случайных чисел.** Один seed — один и тот же матч.
   Случайность для солдата считается из (seed, тик, id), поэтому не зависит от порядка
   потоков. Это даёт повторы матчей и воспроизводимые баги.
4. **Контент — это данные.** Оружие, солдаты, ИИ, карты лежат в файлах (`data/`),
   подхватываются на лету. Как XML в RWR, только формат RON.
5. **Сначала измеряем, потом оптимизируем.** У каждой фазы тика есть замер времени.

## Мир — 2.5D

Как и в RWR, мир по сути плоский: сетка клеток + высоты. Это резко упрощает всё:
видимость, поиск пути, физику, сеть и разрушаемость.

- Клетка = 1 метр. В клетке хранится прочность (0 — пусто, 255 — неразрушаемо).
- Видимость и пули — проход по клеткам (DDA), без физического движка.
- Большие карты делятся на чанки (например 64×64 м): отрисовка, навигация и сеть
  работают по чанкам. `f32` хватает с запасом: на 4 км точность ~0,5 мм.

## Разрушаемость

Разрушенный объект действительно снимает нагрузку с отрисовки, но сама разрушаемость
стоит денег в трёх местах — их нужно заложить сразу:

- **Сеть.** Не передаём каждую клетку. Передаём событие «взрыв: центр, радиус, сила»,
  а клиенты применяют его сами — сетка целочисленная, результат совпадает.
  Подключившемуся позже игроку отдаём список изменённых чанков.
- **Навигация.** Поля путей пересчитываются только там, где карта изменилась,
  и не все за один тик.
- **Видимость.** Работает по той же сетке, обновляется автоматически.

## Воксельные солдаты

Воксели сами по себе не бесплатны: модель «как есть» — это тысячи кубиков.
Поэтому:

- При импорте модель склеивается в меш (greedy meshing) — грани соседних вокселей
  сливаются, остаются сотни треугольников, а не тысячи.
- Солдат состоит из жёстких частей (голова, торс, руки, ноги), анимация — просто
  повороты частей. Никакого скиннинга, очень дёшево.
- Все одинаковые части рисуются одним вызовом (instancing).

## Сеть

- UDP, свой протокол. Сервер шлёт снимки 20–30 раз в секунду.
- Состояние солдата сжимается до ~12 байт (позиция 16 бит на ось, угол 8 бит, …).
- Отправляем только изменения (дельты) и только то, что рядом с игроком.
- Пули по сети не летят: летит событие «выстрел» (кто, куда, seed), трассеры клиент
  рисует сам.
- Оценка: 200 солдат × 12 байт × 20 Гц ≈ 48 КБ/с без оптимизаций, 10–20 КБ/с с ними.

## Крейты

```
crates/
  wind_sim      симуляция: карта, солдаты, ИИ, пули, захват точек. Без графики.
  wind_net      протокол, снимки, дельты, отсечка по дальности, чанки карты
  wind_server   выделенный сервер по UDP; с --bench — замер симуляции
  wind_bots     нагрузочные боты-клиенты
  wind_lab      лаборатория: смотрим и крутим симуляцию в окне, интерфейс как в Blender;
                умеет подключаться к серверу и играть за солдата
позже:
  wind_render   wgpu: рельеф, воксельные меши, instancing, тени
  wind_client   игра: камера, ввод, звук, интерфейс
  wind_tools    редакторы: карты, вокселей, оружия
data/           контент (RON), подхватывается на лету
```

Библиотеки: `glam` (математика), `rayon` (потоки), `serde` + `ron` (данные),
`egui`/`eframe` (инструменты). Дальше: `wgpu`, `winit`, `kira` (звук).

## Интерфейс инструментов — как Blender

- Тёмно-серая палитра Blender: панели `#303030`, вьюпорт `#3d3d3d`, акцент `#4772b3`,
  выделение оранжевым `#ffa028`.
- Шапка с меню сверху, слева список объектов (Outliner), справа свойства
  со сворачиваемыми панелями, снизу строка состояния.
- Навигация как в Blender: средняя кнопка мыши — двигать вид, колесо — масштаб.
- Позже: области можно делить и менять им тип редактора, как в Blender.
